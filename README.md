# 青简 OpenLeaf

以本地电子书为中心的开源 Android 阅读器原型。原生 Java + Android 系统控件，无广告、账号、统计 SDK 或第三方运行时依赖。暂定中文名“青简”，可自行更换。许可证为 MIT。

## 想学习这个项目

如果你是想借鉴工程方法而不是直接使用应用，从 **`LEARNING_PATH.md`（一页学习路径）** 开始：5 步读完架构、core 单测、验证方法、一次完整迭代与对标取舍。关键决策的「为什么」在 `docs/adr/`，贡献与门禁规则在 `CONTRIBUTING.md`。本项目从 0.27 到 0.49 共 23 个版本全部经 QA 实机验证，真正的可借鉴资产是流程纪律与决策记录。

## 书内全文查找

打开 TXT / EPUB / MD 书籍后，点击阅读页顶部 **查找**：

1. 输入关键词，选择 **全书** 或 **当前章节**；可开启区分大小写。输入停止后自动查找，也可点击搜索。
2. 结果按章节分组，章名右侧显示命中数，点击章名展开 / 折叠；卡片显示前后文，关键词以强调颜色显示。
3. 点击具体结果，返回阅读页并定位到对应章节和文字；正文高亮全部已列出的匹配，当前匹配单独强调。
4. 阅读页可点击 **上一个 / 下一个** 在匹配间循环，或打开结果列表；**清除**取消高亮并保留当前阅读位置。

采用纯字面匹配，不使用正则、不跨章节拼接匹配，支持重叠命中。每次最多显示10000处，超过时明确提示；关键词最多256个UTF-16代码单元。原文偏移保持UTF-16身份，英文大小写匹配不通过lowercase重写文本，避免索引偏移错误。搜索解析和扫描在后台线程执行，旧关键词任务会取消并丢弃迟到结果。

当前搜索范围是已经导入的一本流式文本书籍；不是书架标题搜索（在书架搜索框），也不是「发现」页的在线书源搜书，暂不支持 PDF 文本层搜索 / OCR。搜索结果预览和取消不写阅读位置，只有明确点击结果返回正文后，正常阅读进度才随页面位置保存。

核心回归：

```sh
javac -encoding UTF-8 --release 17 -d core-tests/build app/src/main/java/org/openleaf/reader/core/BookParser.java app/src/main/java/org/openleaf/reader/core/BookSearch.java core-tests/BookSearchTest.java
java -cp core-tests/build BookSearchTest
```

## 书架自主整理

0.5.0 加入应用内书架整理，不改变手机原文件的位置：

- **新建文件夹**：在书架顶层建立自己的分类，也可在现有文件夹里新建子分类。文件夹名称不可为空、包含斜杠或与同层名称重复。
- **整理 / 多选**：进入整理模式，勾选书籍；可选择当前页、取消选择，选中项可跨分页保留。切换目录或改变搜索范围会清空选择，避免把不同位置的移动语义混在一起。
- **归档到**：把选中书籍加入目标文件夹，保留它们原来的归档位置。同一本书仍只有一个应用副本和阅读进度。
- **移动到**：在具体文件夹内操作时，只移出当前文件夹并加入目标，其他归档位置保留；在“全部书籍”、全局搜索或“未分类”中操作时，会在确认后改为只归档到目标目录。
- **移出文件夹**：撤销当前文件夹的归档关系；在全局范围则撤销所选书籍的全部归档。书籍保留，可在“全部书籍”查看；没有任何目录关联时显示在“未分类”。
- **文件夹管理**：长按文件夹可以重命名或删除。删除文件夹会同时删除下级文件夹的归档关系，但保留书籍、阅读进度和原文件；若某书没有剩余归档位置，就回到“未分类”。
- **排序**：书名、最近导入或最近阅读；排序选择会保存。最近阅读从该版本开始记录，不会伪造旧书的打开时间。

移动 / 移出均需要确认操作范围，不会调用原文件删除接口。批量操作使用单个 SQLite 事务，包含无效书籍或目标时不会只移动一部分。来源目录和自建文件夹可以同时使用；来源显示名与系统目录身份分开保存。

### 珍藏筛选
在书籍详情页勾选「珍藏」后，书架模式行的「★ 珍藏」按全部书籍范围集中显示这些书，列表 / 网格卡片以星标标识。筛选状态会保存；可与书名 / 标签搜索叠加，切换「全部书籍 / 文件夹 / 最近阅读」或按返回键即退出筛选。筛选只改变展示，不修改归档、进度或原文件。

## 从书架删除文件

每本书的卡片都有 **删除** 按钮，长按书籍也可进入同一页面：

1. **仅从书架移除（保留原文件）**：确认后删除书籍记录、阅读进度和所有文件夹归档关联；原文件不删除。旧版本遗留的应用内副本会一并删除。
2. **删除选中的原文件及书架副本**：先勾选明确的来源路径，再确认删除范围。应用重新核对原文件的 SHA256 与书架记录一致，然后通过系统文档提供器删除；所有选中项均成功后才移除书架副本。未勾选的其他来源文件保留。

原文件删除不可撤销。一个来源失败时，已成功删除的原文件不会自动恢复；书架副本与进度保留，并显示成功 / 失败详情，失败项不会自动重试。源文件已经变化或选择了其他内容时，应用拒绝删除。

0.4.0 会记录新导入及重复导入文件的来源。同一文档的 tree URI 与直接 document URI 按文档身份去重。同内容的不同源文件分别列出，需要逐项选择。SQLite v1 / v2 升级到 v3 只新增来源表，原书籍、目录及进度不变。

旧书没有记录来源，或原有授权只有读取权限时，可点 **选择或重新授权原文件**，用系统选择器选择正确原文件；系统授予的读写权限是删除的前提。应用会先核对内容，记录来源后仍需再次勾选并确认，不会因为重新授权就立即删除。若文件提供器不支持删除、授权失效或文件已不存在，会显示错误并保留书架副本。

此功能不申请管理所有文件权限，不删除目录，不扫描未授权位置。每次最多勾选 500 个来源，未勾选的原文件保持不变。测试只对应用自己创建的合成文件执行真实删除，不会删除用户书籍。

## 导入后按文件夹归档

0.3.0 起，从文件夹批量导入的书籍自动保留来源目录层级。例如选择 `Books`，其中有 `小说/科幻/一本书.epub`，书架显示为：

```text
来源文件夹
  Books
    小说
      科幻
        一本书
  未分类
```

- 书架默认进入“来源文件夹”，点击文件夹逐级浏览；使用“返回上一级”或顶部路径导航返回。目录数量标注“当前层”，不把子目录中的书籍数算作直接藏书数。
- “全部书籍”和全局书名搜索可以跨目录查找，书籍在全局只显示一次。清空搜索会回到原目录。
- 同一本书从不同目录导入，会在对应的多个归档目录下显示，但只保留一条书籍记录和同一份阅读进度。重新扫描同一个来源不会重复建立书籍或目录关联。
- 两个来源目录即使名称相同，也按系统授权 URI 分开保存，不仅凭名称合并。
- 旧版书籍和新增单文件导入的书籍先放在“未分类”。旧版没有记录来源，无法凭空恢复历史目录；重新扫描原目录并点击导入，就会通过内容去重给已有书籍补充归档，不重置进度。应选择与预期归档一致的上级总目录。
- 归档是应用数据库中的整理关系，不会移动或改名手机原文件。书架删除入口提供两种范围：仅移除应用副本保留原件；或另外勾选并确认删除对应原文件。删除书架副本会同时移除所有归档关联及进度。
- 可新建、重命名和删除书架文件夹；来源目录的重命名只改变应用显示名，重新扫描不会覆盖。删除来源归档后再扫描该来源，会重新创建来源归档。暂不提供文件夹整体拖拽移动或跟随手机原目录自动同步。

## 导入设置页

文件夹导入页提供以下设置：

- 文件夹：选择目录或扫描上次授权目录。
- 文件格式：EPUB、PDF、TXT/MD、MOBI/AZW3，可按格式取消勾选；扫描器会递归目录。
- 文件大小上限：单文件（EPUB / PDF / TXT / MD / 书包）最高 512 MiB，默认勾选阈值 512 MB；TXT/MD 超过 32 MiB 时导入校验自动切换为流式逐行校验，不保留整本解码文本，避免导入阶段 OOM。超阈值的候选不默认选中，可手动勾选尝试。
- 直接引用原文件（不复制到书库）：当前版本固定开启且不可取消。导入只登记原文件 URI、内容哈希与书籍元数据，阅读时直接访问原文件；手机原文件不会被修改。移动、删除原文件或撤销目录授权后需重新关联。SHA256 去重、阅读进度和删除前的内容校验仍基于原文件。旧版本遗留的副本继续可读。
- 自动导入此文件夹中的新书：保存该偏好作为后续能力入口；当前版本仍需要手动点击扫描，应用保持运行不代表已实现系统级后台监视。
- 从子文件夹创建分组：默认开启，作为**新导入的默认值**；关闭后，扫描到的文件默认归档到所选导入文件夹的直接层级。

筛选只改变结果列表显示，导入范围由勾选状态决定。扫描结果标题显示 `扫描结果（N）`，下方显示总数、选中数量、大小、重复和失败统计。点击 **导入选中的文件** 后先出现 **导入确认** 弹层，列出选中数量与预计大小，并可单独调整 **同时导入目录分组信息**；该确认值只作用于本次导入，并会回写为下次默认值。

1. 在书架点击 **扫描文件夹**，进入批量导入页，再点击 **选择文件夹**。
2. 在系统选择器选择书籍所在的目录，授予读取权限。扫描会包含该目录下的子文件夹。
3. 在扫描结果里按 TXT / MD / EPUB / PDF 筛选，勾选需要的文件，点击 **导入选中的文件**。
4. 等待添加完成，查看已添加、重复、失败统计；返回书架后可按书名搜索。重复内容会保留已有书籍及其进度。

`.olbook` 书包只能通过「添加文件」导入，目录扫描不识别该扩展名。书包清单为 schemaVersion 3，包含可选的分享者署名；导入时若外来书评与本地书评不同，外来书评进入「想法」区并按「分享者 — 书 — 书评」展示，本地书评与其他标签 / 归档仍正常合并，批量导入完成后自动返回书架。

“添加文件”仍保留原来的单次最多 20 个文件选择入口；**目录扫描不受 20 本限制**。默认勾选扫描结果，可手动取消不需要的文件。按 SHA256 比较内容，文件改名或出现在多个子目录中仍会去重；只同名但内容不同的文件可以分别添加。首次升级后第一次导入，会先计算旧书籍的内容哈希。

支持重新扫描上次已持久授权的目录；授权失效时需要重新选择。部分 Android 版本不允许直接授权存储根目录、Download 根目录及 Android/data 等区域，可在可授权的“Books”等子目录中存放书籍。应用不申请“管理所有文件”权限，也不绕过系统目录限制。

为避免异常目录无限遍历，单次最多扫描 100000 个条目、发现 10000 个匹配文件、递归 128 层；触及限制会显示提示，可改选更小的子目录继续导入。目录环与重复文档 ID 会跳过；子目录读取失败会显示问题，不丢弃已发现文件。

扫描和导入在后台工作线程执行，旋转屏幕保留当前会话。可以停止任务，已成功入库的书籍保留；正在进行的一次电子书解析需结束后才能响应取消。会话不是持久后台下载服务，系统杀掉进程后不会自动恢复任务，可重新扫描，已入库内容会去重。当前版本只登记原文件引用，不需要为每本书预留应用内副本空间，但原文件必须保留在授权目录内。

## 运行与构建

要求 JDK 17、Android SDK Platform 35、Build Tools 35.0.0、Gradle 8.13，最低 Android 8.0（API 26）。AGP 固定为 8.13.2，compile / target SDK 为 35。

### Android Studio

1. 用 Android Studio 打开本目录（含 `settings.gradle`）。
2. 设置 Gradle JDK 为 17；通过 SDK Manager 安装 Android SDK Platform 35 和 Build Tools 35.0.0。
3. 完成 Gradle Sync，选择 API 26 或更高版本的设备运行 `app`。

首次同步需要网络访问 Google Maven 和 Maven Central。`local.properties` 可配置本机 `sdk.dir`，不要提交该文件。AGP 在 Windows 上默认拒绝包含非 ASCII 字符的项目路径；建议将项目放在 `C:\dev\openleaf` 等路径。当前中文工作区可在命令行追加 `-Pandroid.overridePathCheck=true --no-watch-fs`；这仅跳过路径预检查，仍应以实际构建结果为准。

### 命令行

先设置 `JAVA_HOME` 和 `ANDROID_HOME`，并将对应工具加入当前终端 PATH。在本目录运行：

```sh
./gradlew --no-daemon assembleDebug lintDebug
```

项目已包含 Gradle Wrapper，首次运行会下载固定版本并校验 SHA256，无需全局安装 Gradle。Windows 使用 `gradlew.bat`；已安装 Gradle 8.13 时，也可用 `gradle` 代替 `./gradlew`。调试安装包位于 `app/build/outputs/apk/debug/app-debug.apk`。调试签名仅适合开发；正式发布需要自行配置签名，仓库不含密钥。

纯 Java 解析器测试不依赖 Android SDK：

```sh
javac -encoding UTF-8 --release 17 -d core-tests/build app/src/main/java/org/openleaf/reader/core/BookParser.java core-tests/BookParserTest.java
java -Xmx512m -cp core-tests/build BookParserTest
```

GitHub Actions 已配置核心测试、Android 构建、Lint 及 APK 构件上传；该工作流须在你的 GitHub 仓库推送后实际运行，其配置存在不代表已经通过远程验证。

## 数据与隐私

- 导入通过系统文档选择器，无需广泛存储权限。当前版本只登记原文件引用，原文件保留在你选择的位置；只有在你选择“删除原文件”、勾选具体来源并确认后，才会通过系统文档提供器删除对应原文件。旧版本导入的副本仍位于应用私有 `files/books/`。
- 元数据保存在 SQLite；从旧版升级时事务性迁移 AtomicFile 管理的 `files/library.json`，保留原书 ID、原书文件、进度与旧索引。阅读设置、位置、收藏保存在 SharedPreferences。不可随机读取的源会使用有大小限制、随书生命周期清理的临时缓存。
- 本地阅读无须联网。网络权限用于用户主动打开网页；网站仍会收到网络请求、IP 等常规连接信息。
- WebView 关闭 JavaScript、Cookie、DOM storage、本地文件及 content URI 访问；不提供 JavaScript bridge，不忽略证书错误，不允许明文 HTTP 导航。
- 无云同步或导出，已关闭系统备份。**卸载应用会删除书籍副本、进度和收藏**，请保留原文件。
- 未对应用内书库副本额外加密，依赖 Android 应用沙箱。

## 格式边界

- 单文件最多 512 MiB（EPUB / PDF / TXT / MD / 书包）；TXT / MD 同为 512 MiB，但超过 32 MiB 时导入校验改走流式路径（有界章节窗口，不整本解码）。EPUB 全 ZIP 展开最多 512 MiB、单项最多 24 MiB、最多 30000 个 ZIP 条目和 5000 个章节 / spine 项；重复引用读取预算 512 MiB 独立计。单章文本最多 20000 个 UTF-16 代码单元。导入校验走轻量元数据路径（只解析 container/OPF 与 ZIP 安全，不构建整本章节），TXT / MD / EPUB 打开走流式章节索引，无全本建索引峰值；多章大书在受限堆下可正常打开，但单个接近 24 MiB 的超大 XHTML 条目在解析时仍有单章瞬态内存峰值，此类书建议在内存充裕的设备上阅读。MOBI / AZW3 打开走流式章节索引，Java 侧无全本章节聚合峰值；native 单段解析仍有瞬态峰值，超大文件建议在内存充裕的设备上阅读。
- EPUB 有两种呈现：**图文版**支持书内嵌 PNG / JPEG / GIF / WebP 位图、表格、注音及白名单基础 CSS，插图可放大查看；**纯文字版**只重排文字。两者都不加载外部图片 / 字体、不执行书内脚本，也不保证还原固定版式、复杂 CSS、原生 SVG、脚注跳转或音视频；不支持 MOBI / AZW 与 DRM 解密。EPUB 详情页会按多级回退自动提取内嵌封面，失败时保留文字占位。书内查找在纯文字版中进行。
- EPUB XHTML 必须是可解析 XML。允许简单 HTML5 doctype，并在本地剥离已识别的 W3C XHTML 标准 DTD 声明，不联网加载；自定义外部 DTD、未知命名实体或损坏 XHTML 的文件可能被拒绝。细节见 [解析器说明](core-tests/README.md)。
- TXT / MD 打开走流式章节索引；EPUB / MOBI 打开时一次性建立章节索引（此阶段仍有短暂内存峰值），随后正文写入私有缓存并按需加载，阅读与搜索阶段只保留少量章节；接近格式上限的大书仍建议在内存充足的设备上打开。
- PDF 不支持密码、文字选择、搜索、批注或手势缩放；使用系统 PdfRenderer，并未实现隔离进程渲染。纵向滚动位置只在配置变更（如旋转）时恢复，冷启动仅恢复页号。仅在受信任文档上试用原型。
- 网站依赖 JavaScript、登录或明文 HTTP 时可能不可用。在线书源仅支持静态 HTTPS GET 与声明式规则，不支持脚本、登录、DRM 或分段正文。应用不自带内容、盗版书源，也不绕过网站访问权限。
- TXT / MD / EPUB 已支持书内全文查找（四种模式）与临时搜索高亮；书籍详情勾选的「珍藏」可在书架按「★ 珍藏」集中筛选。纯文字阅读页支持持久书签 / 高亮 / 下划线 / 删除线 / 笔记，5 色与排序筛选；图文模式（WebView）暂不支持持久标注。排版参数、简繁转换、阅读统计、自动翻页与音量键翻页均在纯文字阅读页可用。**未实现**云同步、TTS 听书、自动更新或无障碍专项适配。
- 排版 / 统计 / 多色标注等能力借鉴自 Koodo Reader、KOReader、LightRead、Anx Reader、legado 等开源阅读器的**功能设计**，均以 OpenLeaf 自有 Java 代码独立实现，不复制其源码；简繁单字表来自 foliate-js（MIT）并保留署名。详见 [多项目本地阅读-合规借鉴与复刻报告](多项目本地阅读-合规借鉴与复刻报告.md)。
- 尚需真机检查 Android 8 / 15、系统字号放大、横屏、后台回收、不同文件选择器和 PDF 大文件。

## 后续建议

1. 先在真机验证导入—阅读—退出—恢复主流程，修复兼容性问题。
2. 继续拆分 Activity 与数据层；引入分章缓存，减少大书内存占用。
3. 接入系统 TTS 听书（语速 / 音调 / 定时关闭 / 原文跟随），前台服务与断点续听。
4. 换用成熟 EPUB 排版引擎前，评估许可证、字体与第三方声明。
5. 在取得内容授权的前提下，扩展 Legado 规则子集并设计可审计的网络正文适配接口。
6. 可选：离线中文重点词标注、原生占位符页面模板、WebDAV 整库同步（借鉴报告中的后续梯队）。
